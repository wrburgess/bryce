# Scripting Rules

**Applies to:** Bundled and CLI scripts shipped in the Config Bundle or a Host App
**Deep doc:** `docs/rules/scripting-postmortems.md` (Tier 2 — deferred; read on demand when a trigger fires)

> Tier-1 Lean Core ([ADR 0004](../docs/adr/0004-two-tier-rules-layer-progressive-context.md)): always-resident invariants. Keep this file lean — push heavy, subsystem-specific case studies down to the deep doc. These are business-neutral, stack-neutral starters; **extend per host** — concrete stack-named examples live in the matching **Stack Overlay** (e.g. `ai-config-rails`), vendored alongside the baseline.

## Patterns

- **Dependency-free by default.** A bundled script must run on a bare runtime in an unknown CI — use the standard library only (no third-party packages, no package manager) unless the host explicitly opts in.
- **Deterministic, greppable output.** Emit stable, parseable lines and exit non-zero on failure, so a Host App or CI can assert on the result.
- **Assume an unknown environment.** Locale, terminal encoding, and redirected pipes vary across hosts and CI runners; write for the least-capable one.

## Anti-Patterns

- **Never emit non-ASCII bytes from a bundled script's stdout/stderr** — because a Host App or CI runner on a non-UTF-8 locale raises `invalid byte sequence` the moment it reads or matches the output. Use ASCII (`->`, not a unicode arrow), or explicitly set the stream encoding. This rule is **author-owned, not machine-enforced**: it governs *runtime output*, whereas the sources deliberately carry non-ASCII bytes elsewhere (em dashes in comments; the functional `EM_DASH` separator constant), so a source-byte scan is the wrong instrument — see [ADR 0011](../docs/adr/0011-ascii-safe-stdout-stays-doc-only.md). The natural catch point is a test that asserts a script's captured output. *(Provenance: issue #5 / PR #14; extend per host.)* **Host (Bryce) opt-in:** the rule scopes by an output's *primary purpose*, not by file location. A **human-facing app CLI** whose job is to render player identity for the HC to read on his single-user UTF-8 host (ADR 0028) — `seed`/`list`, `players:lists`, and `digest` — emits the canonical (NFC) identity in **UTF-8**; a mangled `Acu?a` there is the regression. Portable/CI tooling (`scripts/*`), machine **diagnostics** (`ncaa:probe`), and greppable **bulk/machine-outcome** reporters whose identity fields are deliberately folded for locale-safety *and* forgery-proofing (`batch-add`) stay ASCII. See [ADR 0047](../docs/adr/0047-app-clis-emit-utf8-ascii-scopes-to-machine-output.md) for the per-command table.
- **Never add a third-party dependency to a bundled script** — because the bundle must run without a package manager on a bare runtime; reach for the standard library instead. *(Extend per host.)* **Host (Bryce) opt-in:** this repo's own tooling scripts (`scripts/*.ts`, run via `tsx`) are Host-App tooling, not portable bundle infrastructure, and deliberately use the app's Node/TS toolchain — see [ADR 0039](../docs/adr/0039-repo-tooling-unifies-on-typescript-remove-ruby.md). The neutral rule above still governs any genuinely portable bundled script.
- **Never let a script exit before its buffered output has flushed** — because a forced exit can truncate stdout mid-write on a slow or full pipe, silently dropping lines a Host App or CI is asserting on. Set the exit *code* and return so the runtime drains naturally, or write synchronously. *(In Node: never `process.exit()` right after an async `process.stdout.write()` — set `process.exitCode`, or use `writeSync`.)* *(Provenance: issue #64 / PR #76; extend per host.)*
- **Never let a bundled CLI silently default on a malformed invocation** — because an unknown flag or a missing option value that falls back to a default target makes a guard scan the wrong thing and print a false green; a mis-invocation must fail loudly (a clear usage error + non-zero exit), never pass. *(Provenance: issue #64 / PR #76; extend per host.)*
- **Never widen a guard's matching rule to clear a false alarm without asking which way the new failure points** — because a comparison loosened to stop a false *red* (an input that failed to match and was reported missing) can begin matching inputs it should not, and the same guard then prints a false *green* while enforcing nothing. The two errors are not symmetric: a false red costs someone a few minutes and announces itself, a false green costs the whole guard and is silent. Prefer the narrowest rule that a different, valid input cannot be mistaken for, and let the unmatched case fail loudly. *(Provenance: issue #28 / PR #138 — a UNC case-fold added to match a Windows root also folded POSIX paths with two leading slashes, where casing is significant, and could have let a wrong coverage entry satisfy a floor; the fix removed the rule rather than adding a fourth special case. Extend per host.)*
- **Never ship a guard without first running its own governing convention through it** — because the checker and the prose it enforces are authored in different moments and drift apart silently: the guard goes green on today's files while the *documented instruction* it exists to enforce becomes one a contributor cannot actually follow, and the trap only springs on whoever next obeys the docs. Take the convention's worked examples through the guard — including **the state it tells authors to move to**, not just the state they start in. When the documentation says "do X once Y", assert that *X-after-Y passes*, not merely that *X-before-Y fails*; a guard tested only on its sad path can be a blanket rejection wearing a rule's name. *(Provenance: PR #149 shipped a deep-doc pointer check that rejected every markdown link unconditionally, while `docs/rules/README.md` told authors to promote a backticked path to a link "only once the target file exists" — three such targets existed, so the documented promotion reddened the gate; issue #154 / PR #155. Extend per host.)*
- **Never let a CLI's argument validation drift behind its side-effecting startup** — because keeping only the *cheapest* check up front lets a malformed invocation take locks, open or migrate a database, and fail from a subsystem the operator never reached: a value the preflight misses surfaces as a config error, not a usage error. Validate every argument before the first side effect, and pin the order **by side effect** (assert the artifact is absent), not by reading the code. *(Provenance: issue #141 / PR #181; extend per host.)*
- **Never invoke a project-local tool by bare name on `PATH`** — because a dev-dependency binary is not on `PATH` in a fresh CI shell step even after install, so the script dies with "command not found"; resolve it through the project's own tooling and guard the pre-install case. *(In Node: use `npx tsx` / `node_modules/.bin/tsx`, not bare `tsx`.)* *(Provenance: issue #64 / PR #76; extend per host.)*
- **Never render an upstream-influenced value into a greppable `key=value` line with a fold that preserves spaces** — because stripping control bytes makes a line safe to *display* without making it safe to *parse*: a space still terminates a token, so a crafted upstream string appends text that reads as the run's own fields. Fold every runtime-derived field to one token at the **rendering helper**, so the next field added inherits the safe choice. Not just names — an `err.message` carries the upstream payload's text. *(Provenance: issue #146 / PR #180; extend per host.)*
- **Never test path containment with a case-sensitive compare when the guard's job is to DENY** — because `resolve()` never consults the filesystem, so on a case-insensitive volume (APFS, NTFS) a differently-cased spelling fails the compare while the write still lands in the very directory being protected: the guard reports "outside" and the thing it exists to prevent happens anyway. Fold both sides whatever the anchor; a non-literal anchor needs a locale-safe fold, not a skipped one. *(Provenance: issue #163 / PR #170; extend per host.)*
- **Never case-fold a containment check that GRANTS permission** — because on a case-sensitive volume `/repo/docs/ADR/x` then reads as a descendant of `/repo/docs/adr`, and the guard approves a write outside its anchor. Canonicalize both sides instead; where either does not exist yet and `realpath` would throw, canonicalize each one's nearest existing ancestor and compare the remainder case-sensitively, failing closed on a missing anchor — never widen to a fold to make the check pass. *(Provenance: issue #163 / PR #170; extend per host.)*
- **Never model a format yourself to check something about it — not from today's files, and not from the spec** — because both models are incomplete and fail the same silent way: a checker calibrated on today's habits (one item per line, one marker spelling, one punctuation) passes every conforming spelling it never saw and a routine reformat disables it everywhere at once, while a checker that *enumerates* the grammar is wrong at every construct it did not list. Enumerating harder does not converge, and thinning the candidate set is not a safe simplification either — removing a candidate can let an earlier opener reach a farther partner and match strictly **more**. Prefer a bound you can state as a *property* over one you have to enumerate; where neither is available, run the format's own parser — or ask something that does not require parsing the format at all, which is the standing answer for a dependency-free bundled script. *(Provenance: issue #152 / PR #157, sharpened by issue #159 / PR #162 after eight review rounds; host case study: `docs/rules/scripting-postmortems.md`. Extend per host.)*
- **Never enforce a shared invariant by re-authoring it at each call site** — because copies do not diverge loudly, they diverge by *omission*: the next site that needs the rule is written without it, every site still reads as locally correct, and the gap shows only to someone who reads all of them together. Author it once, export it, and let a new call site inherit the rule rather than remember it — copying a guard's condition is the signal to extract it, not to paste it. *(Provenance: issue #165 / PR #171 — a containment check written three times, enforced twice. Extend per host.)*
